# Code smells found while adding the dedicated Mushaf nav item, fixing the pinch-zoom/page-flip conflict, and scoping audio state (2026-07-13)

These were observed while researching and implementing that change. None of them were fixed as part of it — noted here for a future cleanup pass.

## `source/index.html` (the whole app is one file — no build step, no router)

- **God object `settingsStore`** (~6165 area): mixes Quran-rendering mode (`layout`, `tajweedEnabled`, `mushafEnabled`), tafsir/word-by-word/surah-view visibility, plan/revision settings, UI color, and audio mode in one flat `reactive()` blob with no accessor layer. Any component wanting to read/write any of this touches the same shared object directly.
- **Two independent, non-synchronized controls for the same underlying state**: the font-toggle cycle (`switchFont`) treats `tajweedEnabled` as part of an atomic mode transition (indopak/tajweed/uthmani), while the Settings-modal tajweed checkbox (`v-model="settingsStore.tajweedEnabled"`, around line 4880) mutates it directly, bypassing `switchFont`'s transition logic entirely. The two can drift out of sync.
- **`scrollToSection` is a ~250-line "God function" acting as a fake router**, keyed off string comparisons of `sectionId` (`'quran-text-section'`, `'tafsir-section'`, `'mushaf-section'`, etc.), called from three separately-maintained nav surfaces (desktop dropdown, mobile sidebar, bottom nav) with no central route table. Adding the Mushaf destination meant adding another string-keyed branch to this function rather than registering a route.
- **Desktop dropdown, mobile sidebar, and bottom nav are three hand-duplicated copies of the same nav items.** Adding "Mushaf" required three separate edits (and removing "Quiz" from the bottom nav only, since it still needs to exist in the sidebar). Any future nav change must be made in multiple places and can drift.
- **`isMushaf` conditional sprawl**: many separate `v-if`/`v-else` blocks across the template are gated on `isMushaf` (mistakes section, memorize button, tafsir, word-by-word, background-color picker, etc.) instead of Mushaf being an isolated component with a clean boundary.
- **State not reflected in the URL**: `mushafEnabled`/`tajweedEnabled`/`layout` aren't part of `updateURL()`/`saveUrlState`, unlike `tafsir`/`wordbyword`/`page` — Mushaf mode can't be deep-linked or restored from a shared URL, inconsistent with how the other reading sub-modes are treated.
- **Bespoke, duplicated localStorage+IndexedDB persistence dance for `audioPlayMode`** (now `audioPlayModeMushaf`/`audioPlayModeText`): eagerly cached in `localStorage` at store-init time, then reconciled against IndexedDB during `loadStoredData()`, then written to the `plainSettings` blob *and* separately through `persistAudioPlayMode()` on every change. Every other setting only goes through the `plainSettings`/IndexedDB path. This dual mechanism had to be carried forward (and doubled) to keep the per-view split correct instead of being simplified.
- **`switchFont` remains a large, branchy function** even after this change extracted its data-reload block into `reloadQuranDataForLayout` — it still mixes settings mutation, conditional font reload, and toast messaging in one place.

## `source/resources/js/utils/touchHelper.js`

- **Magic numbers with no documented rationale**: `threshold: 50`, `maxDuration: 500`/`400`, `ratioThreshold: 1.5`, `maxDistance: 15`, debounce `delay: 300` are all hardcoded defaults with no comment tying them to real device/gesture testing.
- **No `event.preventDefault()` anywhere in `createSwipeHandler`**, so it doesn't coordinate with the browser's own native scroll/pinch-zoom handling — it only reacts after the fact rather than declaring intent up front.

## `source/resources/js/components/QuranAudioPlayerComponent.js`

- **All playback-progress state was (and mostly still is) component-local `data()`** (`isPlaying`, `currentTime`, `pageAudioUrls`, spaced-repetition/AB-repeat position, etc.), unpersisted across reloads. The per-mode snapshot map added by this change (`modeSnapshots`) works around the symptom (view switches wiping progress) but the state is still fragile to any other path that might unmount/remount this component — e.g. `settingsStore.showSurahView` fully destroys/recreates the whole reading area (including the audio player) via `<template v-if="!settingsStore.showSurahView">` in `index.html`, which would still wipe everything including the new per-mode snapshots.
- **Test duplicates production logic instead of importing it**: `tests/unit/mushafView.test.js` reimplements `getMushafImageUrl` as a standalone copy of the `mushafImageUrl` computed in `index.html`, because `index.html` isn't a module and can't be imported. Logic can silently diverge between the production code and the test's copy. The same risk now applies to the new `isMushafMode` restore-vs-reload logic — there's no test importing the real implementation.
